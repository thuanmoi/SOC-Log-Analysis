# Execution Report — Authentication Anomaly Detector

## Objective

Validate the detector against the included sample authentication log and check that the detection logic behaves as expected across positive and negative test cases.

## Environment and input

- Runtime: Python 3
- Dependencies: Python standard library
- Input file: `logs/sample_auth.log`
- Dataset: synthetic authentication events; no production or company logs were used

## Commands

Run from the `SOC-Log-Analysis` directory:

```bash
python src/detect_login.py logs/sample_auth.log
PYTHONPATH=src python -m unittest discover -s tests -v
```

## Observed result

The sample execution produced one alert:

```text
Alerts found: 1
SUSPICIOUS_LOGIN user=alice src_ip=192.0.2.10 failed_attempts=3 success_time=2026-10-01T09:30:10+00:00 line=4
```

The five unit tests passed. They cover:
- Three failures followed by success inside the time window.
- Only two failures before success.
- Failures outside the five-minute window.
- Events belonging to different users.
- Malformed input.

Captured text output is available in `../evidence/sample_run_output.txt` and `../evidence/unit_test_output.txt`.

## Triage assessment

The event sequence is suspicious because a successful login follows several failures from the same source. It is not enough by itself to conclude that an account was compromised. For a real alert, I would check whether the IP address, device, and login time are expected; review MFA and nearby authentication events; and inspect subsequent account or data activity.

## Limitations and next steps

The input is synthetic, the parser accepts only the documented format, and the algorithm assumes timestamp-ordered events. Next improvements could include sorting or rejecting out-of-order events, adding configurable thresholds, supporting additional event types, and emitting structured JSON for ingestion by another tool.
